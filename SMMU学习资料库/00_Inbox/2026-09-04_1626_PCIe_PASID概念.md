# PCIe PASID 概念

## 一句话定义

**PASID（Process Address Space ID）是 PCIe transaction 携带的进程/地址空间身份标签，用来区分同一个 PCIe Device 当前代表哪个 Process 发起访问。**

## 为什么需要 PASID

Requester ID / BDF 只能回答：

```text
“哪个 PCIe Device / Function 发来的？”
```

但同一个设备可能同时服务多个进程：

```text
GPU
├─ Process A
├─ Process B
└─ Process C
```

不同进程甚至可以使用相同 VA：

```text
Process A: VA 0x4000 → PA_A
Process B: VA 0x4000 → PA_B
```

因此 transaction 还需要 PASID 来回答：

```text
“这个 Device 当前代表哪个 Process？”
```

例如：

```text
Requester ID = GPU
PASID        = Process A
Address      = 0x4000
```

含义就是：

> **GPU 代表 Process A 访问 VA 0x4000。**

## 与 Arm SMMU 的对应关系

```text
PCIe Requester ID  →  SMMU StreamID
PCIe PASID         →  SMMU SubstreamID / SSID
```

SMMU 中进一步：

```text
SID  → STE          → 找设备/Stream
SSID → CD           → 找进程 Context
CD   → ASID + TTBR  → 找 Process Page Table
```

因此：

> **Requester ID 找设备，PASID 找进程；进入 SMMU 后就是 SID 找 Stream，SSID 找 Process Context。**

## 和 SVA / ATS / PRI 的关系

- **SVA**：PASID 让 Device 能绑定并直接使用某个 Process 的虚拟地址空间。
- **ATS**：PASID 指明“按哪个 Process 的地址空间查询 translation”。
- **PRI**：缺页时 PASID 帮助软件识别“哪个 Process 的哪个 VA 发生 page fault”。

## 易混淆点

**PASID 是 identity，不是 permission。**

它只说明 transaction 属于哪个地址空间；真正的访问权限仍由 SVA bind、STE/CD、Page Table Permission、Stage 2 等机制决定。

## 面试式总结

> **PCIe PASID 是同一 PCIe Device 内部区分多个 Process Address Space 的 transaction identity。Requester ID 区分设备，PASID 区分进程；进入 Arm SMMU 后，PASID 通常映射为 SSID，由 SSID 选择 Context Descriptor，再取得 ASID、TTBR 等 Stage 1 translation context，因此它是 SVA、ATS 和 PRI 的重要基础。**

### 一句话记忆

> **Requester ID 找设备，PASID 找进程；SMMU 里 SID 找 Stream，SSID 找 Process Context。**
