# DMA：工作机制、SoC 典型应用与 SMMU 关系

## 这篇要解决的问题

DMA 讨论的是：**谁来搬数据、为什么不让 CPU 逐 beat 搬、搬运时在 SoC 总线和 SMMU 中处于什么位置。**

它和 PCIe Root Complex 会在“PCIe Device 自己发起 DMA”场景中相遇，但 DMA 本身并不依赖 PCIe，也不属于 Root Complex 的子概念。

---

## 1. DMA 是什么

DMA（Direct Memory Access）允许 DMA Controller 或具备 DMA 能力的 Device，在不由 CPU 逐个数据 beat 搬运的情况下，主动完成数据传输。

没有 DMA：

```text
Peripheral
   ↓
  CPU
   ↓
Memory
```

有 DMA：

```text
Peripheral
    ↓
DMA Engine
    ↓
Memory
```

CPU 通常只负责：

```text
配置源地址
配置目的地址
配置长度 / burst / channel
启动任务
等待 completion / interrupt
```

因此：

> **CPU 决定“搬什么、搬到哪”，DMA 负责“真正搬”。**

---

## 2. DMA Controller 本质上是 Bus Master / Requester

从 SoC 总线视角，DMA 并不是简单的寄存器外设，而是能主动发起 transaction 的 requester。

典型 AXI 系统：

```text
CPU
DMA
GPU
USB
Ethernet
PCIe
   ↓
AXI / CHI Interconnect
   ↓
DDR / Peripheral
```

所以 DMA 设计要考虑：

- address
- AXI ID
- burst length
- outstanding transaction
- QoS
- backpressure
- cache/coherency 属性

---

## 3. 三类最典型的数据搬运

### Peripheral → Memory

例如 UART RX：

```text
UART RX FIFO
   ↓
DMA
   ↓
DDR Buffer
```

### Memory → Peripheral

例如 Audio Playback：

```text
DDR PCM Buffer
   ↓
DMA
   ↓
I2S / Audio Controller
```

### Memory → Memory

```text
DDR A
 ↓
DMA
 ↓
DDR B
```

典型用于 memcpy、buffer copy、数据重排等。

---

## 4. DMA 为什么常有 FIFO

外设与 DDR 的速率往往不匹配。

例如：

```text
DDR：高带宽 burst
UART：低速字节流
```

DMA 可以通过 FIFO 解耦：

```text
DDR
 ↓ burst read
DMA FIFO
 ↓ 按外设节奏输出
UART
```

反方向同理：

```text
UART
 ↓
DMA FIFO
 ↓ burst write
DDR
```

FIFO 的意义不是“存完整数据”，而是**吸收速率差、提升总线 burst 效率、降低两端耦合**。

---

## 5. Peripheral Handshake 为什么重要

外设 DMA 通常不是 DMA 想读就读，而是由 peripheral request 控制：

```text
Peripheral
   │ DMA Request
   ▼
DMA
   │ transfer
   ▼
Peripheral / request deassert
```

这样可以避免：

- FIFO 为空时继续读；
- FIFO 满时继续写；
- 重复消费同一份数据；
- 丢失数据节拍。

---

## 6. SoC 中的典型 DMA 应用

### UART

```text
UART FIFO
  ↓
DMA
  ↓
DDR
```

价值：减少 CPU 高频中断和逐字节搬运。

### Camera

```text
Camera Sensor
   ↓
MIPI CSI / Camera Controller
   ↓
DMA Engine
   ↓
DDR Frame Buffer
```

Camera 是很典型的高带宽持续数据流，DMA 几乎是必需的。

### Audio

```text
DDR Audio Buffer
   ↓
DMA
   ↓
I2S / Codec
```

常结合 Ping-Pong / Circular Buffer：

```text
DMA 播放 Buffer A
同时 CPU 填 Buffer B
然后交换
```

### Ethernet

```text
MAC
 ↓
DMA Engine
 ↓
DDR Packet Buffer
```

高速网络数据不能靠 CPU 逐 byte 搬运。

### PCIe / NVMe / NIC

很多 PCIe Device 内部本身就有 DMA engine：

```text
PCIe Endpoint
   │ DMA Memory Read/Write
   ▼
Root Complex
   ▼
SMMU
   ▼
DDR
```

这里**并不需要再经过 SoC 中的通用 DMA Controller**。

所以更广义地说：

> **DMA 是一种主动访问 memory 完成数据搬运的能力，不等于某一个固定的“DMA IP”。**

---

## 7. Descriptor / Scatter-Gather DMA

真实系统的数据经常不物理连续，所以 DMA 常使用 descriptor：

```text
Descriptor 0
src=A
len=4KB

Descriptor 1
src=C
len=2KB

Descriptor 2
...
```

DMA 自动执行：

```text
Fetch Descriptor
   ↓
执行 Transfer
   ↓
Fetch Next Descriptor
```

Scatter-Gather 的价值是：

> **允许多个离散 buffer 在软件看来组成一次连续 DMA 任务。**

网络 packet、storage request、camera buffer queue 中都很常见。

---

## 8. DMA 为什么需要 SMMU

DMA requester 具备主动访问 memory 的能力，这本身就意味着安全风险。

如果直接给 Device 使用 PA：

```text
DMA Device
   ↓ PA
DDR
```

那么一旦 Device/driver 配错地址，可能访问不属于自己的内存区域。

带 SMMU 后：

```text
DMA Device
   │ IOVA
   ▼
SMMU
   │ Translation + Permission
   ▼
PA
   ▼
DDR
```

Software 只映射允许 Device 访问的 buffer：

```text
IOVA 0x1000
   ↓
SMMU
   ↓
PA 0x8000_1000
```

未映射 IOVA：

```text
→ Translation Fault
```

所以 SMMU 对 DMA 的核心价值是：

> **地址虚拟化 + DMA isolation。**

---

## 9. 为什么叫 IOVA

CPU：

```text
VA
 ↓ CPU MMU
PA
```

Device：

```text
IOVA
 ↓ SMMU
PA
```

因此 IOVA 可以理解成 Device 看到的虚拟地址。

传统 DMA mapping：

```text
Process VA
  ↓ Software / Driver
Device IOVA
  ↓ SMMU
PA
```

SVA 则是进一步让 Device 能够直接使用 Process VA；这部分已经在现有 `SVA共享虚拟地址与进程设备绑定` 条目中单独整理，本篇不重复展开。

---

## 10. 一个完整 Camera DMA 例子

```text
Software
   ↓ 分配 frame buffer
   ↓ 建立 SMMU mapping
   ↓ 得到 IOVA
   ↓ 配置 Camera DMA dst=IOVA
Camera Sensor
   ↓
Camera Controller / DMA
   ↓ IOVA write
SMMU
   ↓ IOVA→PA
DDR Frame Buffer
   ↓
Frame Done IRQ
   ↓
CPU处理图像
```

这里每一层职责都很清楚：

```text
CPU/Driver
→ 配置 buffer 和任务

DMA
→ 真正搬 frame 数据

SMMU
→ 约束 DMA 能访问哪些内存
```

---

## RTL / 集成视角关注点

1. DMA 是独立 AXI Master 还是挂在 Peripheral Controller 内部。
2. Source/Destination address 使用 PA 还是 IOVA。
3. 是否经过 SMMU/TBU。
4. Burst、outstanding、FIFO depth 是否满足性能要求。
5. DMA request/ack handshake 是否正确。
6. Cache coherency：DMA buffer 是否 coherent，是否需要 cache maintenance。
7. Descriptor fetch 本身是否也经过 SMMU translation。
8. Error response / translation fault 后 DMA 是否能停止并正确上报。

---

## 验证关注点

```text
Case 1: 正常 Peripheral→Memory DMA
→ 数据长度、地址、顺序正确

Case 2: backpressure / FIFO 满空
→ 不丢数据、不重复数据

Case 3: Scatter-Gather
→ descriptor 链顺序与边界正确

Case 4: invalid IOVA
→ SMMU fault
→ DMA 不得越权写目标 memory

Case 5: completion interrupt
→ DMA status 与 IRQ 一致

Case 6: cache-coherent / non-coherent buffer
→ 验证 CPU 与 Device 数据可见性
```

---

## 面试式总结

> **DMA 是一种让 DMA Controller 或 Device 在不由 CPU 逐数据搬运的情况下主动访问 Memory 的机制。DMA 通常作为 AXI Master，通过 source/destination、length、burst、descriptor 等配置完成 Peripheral↔Memory 或 Memory↔Memory 数据传输。典型场景包括 UART、Audio、Camera、Ethernet 和 PCIe Device。对于带 SMMU 的 SoC，DMA requester 通常使用 IOVA，由 SMMU 完成 IOVA→PA translation 和 permission check，从而实现 DMA isolation。**

### 一句话记忆

> **DMA 负责“搬数据”，SMMU 负责“限制它能搬到哪、能从哪搬”。**
